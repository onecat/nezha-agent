# Linux local upgrade coordinator

The coordinator joins the durable ledger and atomic file installer through an explicit local Worker contract. It stops the old worker before replacement, starts the candidate, requires independent health confirmation of the exact new process, and only then persists succeeded. A failed start, health check, expired task or cancelled request invokes local bounded recovery independent of the original request context. Recovery restores the previous binary, starts it, and requires its health confirmation before recording rolled_back. Failed recovery leaves rolling_back and stops the unhealthy worker. An ambiguous ledger write stops the worker and requires reopen before further operations. Recovery at startup abandons an uninstalled verified task or restores an interrupted install; it never assumes a crashed health check succeeded.

The actual Worker implementation, process-specific readiness channel and durable trusted previous-version metadata are NOT implemented here. Old version is an explicitly trusted local caller input. The test double checks real replacement bytes, not real service health. The state store, signed package, file swap and restart/reopen are real temporary-directory operations. The coordinator does not register a network endpoint, enable upgrades, provision keys, or start a production service. Future supervisor wiring must own the worker process exclusively, enforce deadlines, reconcile orphan backups and verify health through a local process-bound channel with successful authenticated reporting. Linux only. No Windows or actual end-to-end upgrade claim.
