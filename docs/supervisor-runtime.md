# Linux supervisor runtime (development)

The separate cmd/supervisor executable requires an absolute private local JSON file with enabled=true, server_id, initial_sequence, initial_version, agent_config, install_dir, state_dir, stage_dir and keys (hex Ed25519 public keys by key ID). All paths must be absolute, state and staging directories private and pre-created; the fixed nezha-agent executable and ancestors must be trusted. The first invocation with --initialize provisions the ledger once; normal startup never resets it. No remote paths or commands are accepted. Do not enable until qualification. The ordinary Agent executable remains unchanged in default behavior.

Ledger schema 2 stores installed/previous version and receipt acknowledgement atomically with sequence and task. Existing development schema-1 ledgers deliberately fail closed; do not delete them to bypass high-water. Normal startup recovers an interrupted installation before starting normal work. It then polls the authenticated Dashboard every 15 seconds, refuses new work until the previous durable terminal result is acknowledged, and exits on child death for a local service manager to restart. Uncertain grants and rejected receipts can require operator reconciliation and pause further upgrades; no automatic reset is allowed. The previous version remains trusted local state. The service manager must contain the entire process group and handle cleanup. No systemd install unit or production deployment is included yet. Staging orphan cleanup, actual Dashboard integration, arm64 native qualification and explicit operator reconciliation remain pending. Windows supervisor is unavailable; Windows monitoring builds continue.
