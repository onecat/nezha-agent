# Linux real worker lifecycle and readiness

The local Process implements the upgrade coordinator Worker interface. It starts the fixed local Agent executable with an operator-configured private JSON path, without a shell or remote arguments. Two anonymous inherited pipes provide per-launch readiness and parent-lifetime cancellation. The actual Agent sends its version only after both authenticated host and state reports have received positive receipts; a different launch cannot reuse the old pipe proof. The parent verifies the exact expected version and a short stabilization interval. Stop requests graceful shutdown and escalates to killing and reaping the child before another Start. Parent pipe closure requests cancellation, but it is not an absolute guarantee of termination if a child is stuck in an OS call. A service manager should contain the entire process group/cgroup.

The Linux integration test builds the actual Agent executable, starts it as a real subprocess against a local TLS gRPC fixture, verifies accepted reports and readiness, rejects a wrong version and tests that a fresh worker with rejected state receipts cannot inherit old readiness. It does not run the actual Dashboard executable or perform a full upgrade. No external IP discovery occurs in the test. Readiness is a one-shot signal, not ongoing health monitoring. The Worker is not yet wired into a production supervisor executable. Trusted prior-version metadata, startup recovery, task transport and Windows lifecycle are still outstanding. Upgrades remain disabled.
