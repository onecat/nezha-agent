# Local monitoring and reporting

Original Agent code using the inherited Dashboard model and the separately licensed gopsutil v4.26.10 dependency. No official Nezha Agent source is imported. The collector does not call public IP, geolocation, or update services.

Initial metrics: CPU, memory, swap, system/root filesystem capacity and usage, boot time, uptime, OS, architecture, cumulative network counters and calculated transfer rates. By default network counters are OS aggregate counters, not billing-grade WAN-only traffic; virtual and loopback interface traffic may be included. The optional JSON setting `"exclude_network_interfaces":["lo","docker0"]` excludes exact interface names from cumulative traffic and speed calculations. When configured, per-interface counters are summed with overflow protection. An exclusion matching every interface reports zero traffic. Changing exclusions requires restarting the Agent and resets the rate baseline. Interface renames and OS-specific names are not automatically detected. Network resets and first measurements produce zero rate. Load averages, process count, TCP and UDP socket counts are now collected on a best-effort basis. Restricted container and Windows environments may return unavailable metrics; these remain zero rather than failing core monitoring. Temperature sensors are best-effort, sorted, deduplicated by sensor key, capped at 64, and omit invalid/out-of-range readings; unsupported sensors produce an empty list. Counts reflect the visibility of the Agent process and socket APIs, not necessarily every process/socket on the host. GPU utilization is best-effort on Linux: reads available DRM sysfs `cardN/device/gpu_busy_percent` (typically AMD, some Intel), averages available GPU readings, and reports card identifiers/vendor labels. Unsupported devices (including NVIDIA without a compatible sysfs metric), inaccessible sysfs and Windows report zero GPU utilization and no GPU names. Zero cannot distinguish unsupported from idle. No vendor tools or network calls are executed.

The reporting loop sends host before state, refreshes host every five minutes and retries failed reports with capped exponential backoff. Caller supplies context and transport; the loop has no task execution or upgrade capability. No executable or service integration is added in this commit. Real local sampling tests run on Linux and Windows; the retry/order tests use a mock reporter, not an actual Dashboard. Dependency checksums will be locked after CI resolves the new dependency.
