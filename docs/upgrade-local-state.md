# Agent local durable upgrade state (Linux)

The local state ledger is independent of Dashboard state. One-time provisioning explicitly binds the ledger to the local server ID and installed release sequence. Ordinary open never recreates missing state. An exclusive process lock, private regular files, bounded canonical JSON, atomic replacement and file/directory fsync provide crash-safe state on a trusted local Linux filesystem. An ambiguous persistence error poisons the handle until reopen. Operator-controlled directory and ancestors, correct ownership, and preservation of the state across service upgrades are prerequisites. Do not delete or restore an old ledger; this is not protection against privileged local attackers or disk snapshot rollback.

After independent package verification and task authentication, ReserveVerified atomically consumes the sequence and records the verified task before installation. Advance uses identity/state/expiry compare-and-swap, preserves the sequence after rollback, and allows recovery transitions after expiry. The ledger retains only the latest accepted verified task; replay prevention relies on strictly increasing release sequences. A failed pre-verification transfer does not consume a sequence. Initial provisioning is not yet wired into the CLI.

Linux amd64/arm64 share the implementation. Windows durable state and service locking remain unimplemented. This code does not install or replace executables, perform health checks, authenticate a network request or execute rollback. Those operations must be implemented before enabling upgrades. Tests exercise exclusive access, reopen after install-state persistence, expired rollback, replay rejection, and corruption or missing-state refusal.
