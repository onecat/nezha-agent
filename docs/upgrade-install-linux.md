# Linux file replacement boundary

The local installer accepts only a verified task already reserved in the durable Linux ledger. It verifies the signed archive again, matches the exact task and native platform, extracts only the fixed executable name and rechecks its hash. It creates a same-filesystem candidate and preserves the old executable using a non-overwriting hard link. File and directory sync precede the durable installing transition; only then is the candidate atomically renamed over the fixed executable. The ledger enters health_check only after the rename and directory sync.

Restore changes the ledger to rolling_back before replacing the target with the preserved old contents; it is retryable after restart and does not lower the sequence. It intentionally does not mark rolled_back: a future supervisor must restart and independently check the old worker. Likewise the new worker must pass health checks before succeeded. The module is Linux-only, requires a private trusted operator-owned local installation directory and exclusive state store, and must be invoked by a separate serialized supervisor with worker quiescence. It does not execute any program, take remote filesystem paths, install a service, expose an RPC, or automatically delete backups. Orphan candidates and backups from interruptions before the installing transition require reconciliation. Linux file capabilities and extended attributes are not preserved; the expected Agent binary has none. Tests replace synthetic non-executable fixture contents in temporary directories, then reopen the ledger and restore. They are not actual service restart or power-loss tests.
