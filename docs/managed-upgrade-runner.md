# Linux managed upgrade orchestration (development)

Runner joins the existing authenticated TLS download client, local sequence reservation, one-use server grant, process supervisor and terminal reporting. Explicit local enablement and provisioned trusted keys are required. Download and verification do not authorize execution. After durable reservation the runner requests a single grant; an uncertain response consumes the sequence but does not stop or replace the worker. A confirmed grant permits the local supervisor to apply the verified archive. Only an exact terminal snapshot reloaded from the ledger is reported, with a separate bounded context. Unresolved rollback or ambiguous local persistence is not reported as success. RetryResult never reinstalls.

Production service/CLI startup, durable receipt acknowledgement gating across restarts, trusted current/previous-version metadata, polling, actual Dashboard eligibility, and cross-repository integration are still pending. Callers must perform startup recovery and reconcile a prior terminal result before running another task. The new runner is not enabled in the ordinary Agent executable. The existing local real-process tests and TLS download tests remain in CI; this orchestration needs a dedicated cross-repository live test. Windows managed upgrades remain disabled.
